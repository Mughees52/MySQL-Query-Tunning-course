your new job

Welcome to UrbanCart

An online retailer whose database was built in a hurry — and has been slowing down ever since. You just inherited it.

the size
5.5M rows · ~350 MB
Not big data — and that's the point. If queries are slow at this size, hardware won't save you at ten times it.
6 tables · fits in the buffer pool
the schema crime
Zero secondary indexes
Only primary keys exist. Every lookup that isn't by id reads the entire table, every time, for every user.
every email login: full scan
the symptoms
45 ms lookups · 4 s reports
A single customer lookup burns 45 ms of CPU; the morning revenue report takes four seconds and gets refreshed all day.
an index does the lookup in 9 µs
your job over the next four hours: fix it — measuring every step, so you always know whether you actually made things better
the 45 ms → 9 µs lookup is exercise 2.2 · the 4 s report is the chapter-1 baseline you'll rescue in the capstone

before lesson one

Setup: one command

Requirement: Docker. The container runs MySQL 8 on port 3307, so it won't collide with anything you already have.

# build and seed (a few minutes, one-time)
cd setup
./setup.sh

# connect
docker exec -it mysql-tuning-course mysql -uroot -pcourse urbancart
sanity check: SELECT COUNT(*) FROM orders; → 1,200,000 · you're ready
hardware varies, so your absolute times will differ from the printed ones — the ratios and the plans will not
everything in this course runs inside this one container — nothing else to install
